# Claude_Code_SAP

Claude Code로 만든 ABAP 개발물을 abapGit으로 관리하는 저장소입니다.

## 패키지 구조

| 단계 | 패키지 이름 | GitHub 폴더 | 예시 |
|---|---|---|---|
| 루트 | `$YCLAUDE` | `src/` | |
| 대표 모듈 | `$YCLAUDE_<모듈>` | `src/<모듈>/` | `$YCLAUDE_SD` → `src/sd/` |
| 모듈 하위 | `$YCLAUDE_<모듈>_00X` | `src/<모듈>/00X/` | `$YCLAUDE_SD_001` → `src/sd/001/` |

- 모두 **로컬 패키지**(`$`)입니다. 이관(TR) 대신 GitHub + abapGit으로 시스템 간 이동합니다.
- 오브젝트 이름은 `Y`로 시작합니다.
- 하위 패키지는 Pull 시 abapGit이 자동으로 생성합니다.

## 오브젝트 명명 규칙

모든 오브젝트는 `Y`로 시작합니다. `<모듈>`은 대표 모듈 약어(SD, MM, CA …), `<목적>`은 영어 대문자 단어를 `_`로 연결합니다. 이름은 30자 이내입니다.

| 유형 | 규칙 | 예시 |
|---|---|---|
| 클래스 (글로벌, SE24) | `YCL_<모듈>_<목적>` (번호 없음) | `YCL_SD_ORDER_CREATE`, `YCL_CA_EXCEL_UPLOAD` |
| 로컬 클래스 | `LCL_<목적>` — **ALV용으로만 사용** | `LCL_ALV_EVENT`, `LCL_ALV_HANDLER` |
| 메소드 | 로직 목적 (접두어 없음, 동사로 시작) | `CREATE_ORDER`, `GET_CUSTOMER`, `CHECK_CREDIT` |
| 함수 모듈 | `YF_<모듈>_<목적>` | `YF_SD_ORDER_CREATE`, `YF_CA_EXCEL_UPLOAD` |
| 함수 그룹 | `YFG_<모듈><패키지번호>_<순번 3자리>` | `$YCLAUDE_MD_001`의 첫 함수 그룹 → `YFG_MD001_001` |
| 서브루틴 (FORM) | 로직 목적 (동사로 시작), 목적 단위로 묶어 배치 | `GET_DATA`, `DISPLAY_ALV` |

- 함수 그룹은 이름의 패키지와 같은 패키지에 만듭니다. 순번은 그 패키지 안에서 001부터 올립니다.
- 대표 모듈 패키지(번호 없음)는 패키지번호를 `000`으로 씁니다. (예: `$YCLAUDE_MD` → `YFG_MD000_001`)

### 변수·파라미터 명명 규칙

이름은 `<범위><종류>_<이름>` 형식입니다. (예: `LV_COUNT`, `IT_ORDER`, `GO_ALV`)

**범위 (첫 글자)**

| 글자 | 범위 | 비고 |
|---|---|---|
| `L` | 로컬 변수 | 메소드·서브루틴·함수 안 |
| `G` | 전역 변수 | 프로그램 전역 + **클래스 속성** |
| `I` | IMPORTING 파라미터 | 메소드·함수 모듈 공통 |
| `E` | EXPORTING 파라미터 | 〃 |
| `C` | CHANGING 파라미터 | 〃 |
| `R` | RETURNING 파라미터 | 〃 |

**종류 (두 번째 글자)**

| 글자 | 종류 | 예시 |
|---|---|---|
| `V` | 변수 (단일 값) | `LV_MATNR`, `IV_VBELN`, `RV_RESULT` |
| `S` | 구조체 | `LS_HEADER`, `ES_RETURN` |
| `T` | 내부 테이블 | `LT_ITEM`, `IT_ORDER`, `CT_DATA` |
| `C` | 상수 | `LC_MAX`, `GC_STATUS_OPEN` |
| `O` | 참조 (`REF TO`) | `LO_ALV`, `GO_LOG`, `IO_ORDER` |
| `R` | 레인지 테이블 | `LR_MATNR`, `IR_WERKS`, `RR_DATE` |

**TYPES 선언**

| 접두어 | 종류 | 예시 |
|---|---|---|
| `TV_` | 단일 값 타입 | `TV_AMOUNT` |
| `TS_` | 구조체 타입 | `TS_ORDER` |
| `TT_` | 테이블 타입 | `TT_ORDER` |

**필드 심볼**: 위 규칙을 그대로 `< >` 안에 씁니다. (예: `<LV_VALUE>`, `<LS_ITEM>`, `<LT_DATA>`)

**선택 화면**

| 접두어 | 대상 | 예시 |
|---|---|---|
| `P_` | `PARAMETERS` | `P_WERKS`, `P_TEST` |
| `S_` | `SELECT-OPTIONS` | `S_MATNR`, `S_ERDAT` |

**FORM 파라미터**

| 접두어 | 대상 | 예시 |
|---|---|---|
| `P` + 종류 (`PV_`/`PS_`/`PT_`/`PO_`/`PR_`) | `USING` | `PV_VBELN`, `PS_HEADER`, `PT_ITEM` |
| `C_` | `CHANGING` | `C_RESULT` |
| `PT_` | `TABLES` | `PT_ITEM` |

- `TABLES`는 최대한 피합니다. 값을 바꾸는지 읽기만 하는지 구분되지 않기 때문입니다. 테이블은 `USING`(읽기) 또는 `CHANGING`(변경)으로 넘깁니다.

## 오브젝트 배치 기준

| 패키지 | 무엇을 두나 | 예시 |
|---|---|---|
| 대표 모듈 (`$YCLAUDE_MD`) | 하위 영역 **두 곳 이상이 공통으로** 쓰는 오브젝트 | BP·MM 공통 클래스, 도메인, 구조 |
| 모듈 하위 (`$YCLAUDE_MD_001`) | **한 업무 영역**에서만 쓰는 오브젝트 | `_MD_001` BP, `_MD_002` MM |

- 처음엔 한 영역에서만 쓰다가 다른 영역에서도 쓰게 되면 대표 모듈 패키지로 옮깁니다.
- 참조는 하위 → 대표 모듈 방향만 허용합니다. (하위끼리, 대표 → 하위 참조 금지)
- 루트 `$YCLAUDE`에는 오브젝트를 두지 않습니다.
