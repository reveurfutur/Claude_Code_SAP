# Claude_Code_SAP

Claude Code로 만든 ABAP 개발물을 abapGit으로 관리하는 저장소입니다.

## 패키지 구조

| 단계 | 패키지 이름 | GitHub 폴더 | 예시 |
|---|---|---|---|
| 루트 | `$YCLAUDE` | `src/` | |
| 대표 모듈 | `$YCLAUDE_<모듈>` | `src/<모듈>/` | `$YCLAUDE_SD` → `src/sd/` |
| 모듈 하위 | `$YCLAUDE_<모듈>_00X` | `src/<모듈>/00X/` | `$YCLAUDE_SD_001` → `src/sd/001/` |

- 모두 **로컬 패키지**(`$`)입니다. 이관(TR) 대신 GitHub + abapGit으로 시스템 간 이동합니다.
- 오브젝트 이름은 `Y`로 시작합니다.
- 하위 패키지는 Pull 시 abapGit이 자동으로 생성합니다.

## 오브젝트 명명 규칙

모든 오브젝트는 `Y`로 시작합니다. `<모듈>`은 대표 모듈 약어(SD, MM, CA …), `<목적>`은 영어 대문자 단어를 `_`로 연결합니다. 이름은 30자 이내입니다.

| 유형 | 규칙 | 예시 |
|---|---|---|
| 클래스 (글로벌, SE24) | `YCL_<모듈>_<목적>` (번호 없음) | `YCL_SD_ORDER_CREATE`, `YCL_CA_EXCEL_UPLOAD` |
| 인터페이스 | `YIF_<모듈>_<목적>` | `YIF_SD_ORDER` |
| 예외 클래스 | `YCX_<모듈>_<목적>` | `YCX_SD_ORDER_ERROR` |
| 로컬 클래스 | `LCL_<목적>` — **ALV용으로만 사용** | `LCL_ALV_EVENT`, `LCL_ALV_HANDLER` |
| 메소드 | 로직 목적 (접두어 없음, 동사로 시작) | `CREATE_ORDER`, `GET_CUSTOMER`, `CHECK_CREDIT` |
| 함수 모듈 | `YF_<모듈>_<목적>` | `YF_SD_ORDER_CREATE`, `YF_CA_EXCEL_UPLOAD` |
| 함수 그룹 | `YFG_<모듈><패키지번호>_<순번 3자리>` | `$YCLAUDE_MD_001`의 첫 함수 그룹 → `YFG_MD001_001` |
| 서브루틴 (FORM) | 로직 목적 (동사로 시작), 목적 단위로 묶어 배치 | `GET_DATA`, `DISPLAY_ALV` |

- 함수 그룹은 이름의 패키지와 같은 패키지에 만듭니다. 순번은 그 패키지 안에서 001부터 올립니다.
- 대표 모듈 패키지(번호 없음)는 패키지번호를 `000`으로 씁니다. (예: `$YCLAUDE_MD` → `YFG_MD000_001`)

### 프로그램 · 트랜잭션 코드 · 폼 (패키지별 번호 대역)

프로그램은 `Y<모듈><5자리>`이고, 앞 3자리가 패키지 번호, 뒤 2자리가 순번입니다. 패키지마다 100개씩 대역을 가집니다.

| 패키지 | 번호 대역 | 예시 |
|---|---|---|
| `$YCLAUDE_MD` (대표 모듈 = 000) | `YMD00000` ~ `YMD00099` | `YMD00000` |
| `$YCLAUDE_MD_001` | `YMD00100` ~ `YMD00199` | `YMD00100`, `YMD00101` |
| `$YCLAUDE_MD_002` | `YMD00200` ~ `YMD00299` | `YMD00200` |

| 유형 | 규칙 | 예시 |
|---|---|---|
| 프로그램 | `Y<모듈><패키지 3자리><순번 2자리>` | `YSD00100` (`$YCLAUDE_SD_001`의 첫 프로그램) |
| 공통 Include | `YCACOMMON`, `YCACOMMON_<역할>` (번호 규칙 예외) | `YCACOMMON`, `YCACOMMON_TOP`, `YCACOMMON_F01` |
| Include | `<프로그램>_<역할>` | `YSD00100_TOP`, `_SCR`, `_C01`, `_O01`, `_I01`, `_F01` |
| 트랜잭션 코드 | 프로그램 이름과 동일 | `YSD00100` |
| 트랜잭션 코드 (관리자용) | 프로그램 이름 + `A` | `YSD00100A` |
| Smartforms | `Y<모듈>SF<5자리>` (프로그램과 같은 대역) | `YSDSF00100` |
| Smart Style | `Y<모듈>SS<5자리>` | `YSDSS00100` |
| Adobe Form | `Y<모듈>AF<5자리>` | `YSDAF00100` |
| Adobe Form 인터페이스 | `Y<모듈>AI<5자리>` (폼과 같은 번호) | `YSDAI00100` |

Include 역할: `_TOP` 전역 선언, `_SCR` 선택 화면, `_C01` ALV 로컬 클래스, `_O01` PBO 모듈, `_I01` PAI 모듈, `_F01`~ FORM (목적별로 `_F01`, `_F02` …)

### DDIC

| 유형 | 규칙 | 패키지 | 예시 |
|---|---|---|---|
| 데이터 엘리먼트 | `YE<목적>` | **루트 `$YCLAUDE`** | `YEBUKRS` |
| 도메인 | `YD<목적>` | **루트 `$YCLAUDE`** | `YDBUKRS` |
| 테이블 | `Y<모듈>T<5자리>` | 해당 대표 모듈 패키지 | `YMDT00001` |
| 구조 | `Y<모듈>S<5자리>` | 해당 대표 모듈 패키지 | `YMDS00001` |
| 테이블 타입 | `Y<모듈>TT<5자리>` | 해당 대표 모듈 패키지 | `YMDTT00001` |

- 데이터 엘리먼트·도메인은 모든 모듈이 같이 쓰도록 루트에 모읍니다. 이름은 의미가 드러나게 짓습니다 (표준 필드명이 있으면 그대로 활용).
- 테이블·구조·테이블 타입은 한 영역에서만 쓰더라도 **대표 모듈 패키지**에 둡니다. 번호는 모듈별로 `00001`부터 순서대로 올립니다.

### CDS 뷰

| 유형 | 규칙 | 예시 |
|---|---|---|
| 기본/인터페이스 뷰 | `YI_<모듈>_<목적>` | `YI_SD_SALES_ORDER` |
| 소비(Consumption) 뷰 | `YC_<모듈>_<목적>` | `YC_SD_SALES_ORDER_LIST` |
| SQL 뷰 이름 (구형 `DEFINE VIEW`만) | `Y<모듈>V<5자리>` | `YSDV00001` |
| 접근 제어(DCL)·메타데이터 확장 | 대상 CDS 뷰와 같은 이름 | `YI_SD_SALES_ORDER` |

- CDS 뷰 위치는 일반 오브젝트 배치 기준(대표 모듈 또는 `_00X`)을 따릅니다.
- 가능하면 `DEFINE VIEW ENTITY`를 써서 SQL 뷰 이름이 필요 없게 합니다.

| 유형 | 규칙 | 패키지 | 예시 |
|---|---|---|---|
| 모듈 공통 | `Y<모듈>_000` | 대표 모듈 패키지 | `YMD_000` (예: 001 `&1 건 조회되었습니다`) |

### 변수·파라미터 명명 규칙

이름은 `<범위><종류>_<이름>` 형식입니다. (예: `LV_COUNT`, `IT_ORDER`, `GO_ALV`)

**범위 (첫 글자)**

| 글자 | 범위 | 비고 |
|---|---|---|
| `L` | 로컬 변수 | 메소드·서브루틴·함수 안 |
| `G` | 전역 변수 | 프로그램 전역 + **클래스 속성** |
| `I` | IMPORTING 파라미터 | 메소드·함수 모듈 공통 |
| `E` | EXPORTING 파라미터 | 〃 |
| `C` | CHANGING 파라미터 | 〃 |
| `R` | RETURNING 파라미터 | 〃 |

**종류 (두 번째 글자)**

| 글자 | 종류 | 예시 |
|---|---|---|
| `V` | 변수 (단일 값) | `LV_MATNR`, `IV_VBELN`, `RV_RESULT` |
| `S` | 구조체 | `LS_HEADER`, `ES_RETURN` |
| `T` | 내부 테이블 | `LT_ITEM`, `IT_ORDER`, `CT_DATA` |
| `C` | 상수 | `LC_MAX`, `GC_STATUS_OPEN` |
| `O` | 참조 (`REF TO`) | `LO_ALV`, `GO_LOG`, `IO_ORDER` |
| `R` | 레인지 테이블 | `LR_MATNR`, `IR_WERKS`, `RR_DATE` |

**TYPES 선언**

| 접두어 | 종류 | 예시 |
|---|---|---|
| `TV_` | 단일 값 타입 | `TV_AMOUNT` |
| `TS_` | 구조체 타입 | `TS_ORDER` |
| `TT_` | 테이블 타입 | `TT_ORDER` |

**필드 심볼**: 위 규칙을 그대로 `< >` 안에 씁니다. (예: `<LV_VALUE>`, `<LS_ITEM>`, `<LT_DATA>`)

**선택 화면**

| 접두어 | 대상 | 예시 |
|---|---|---|
| `P_` | `PARAMETERS` | `P_WERKS`, `P_TEST` |
| `S_` | `SELECT-OPTIONS` | `S_MATNR`, `S_ERDAT` |

**FORM 파라미터**

| 접두어 | 대상 | 예시 |
|---|---|---|
| `P` + 종류 (`PV_`/`PS_`/`PT_`/`PO_`/`PR_`) | `USING` | `PV_VBELN`, `PS_HEADER`, `PT_ITEM` |
| `C` + 종류 (`CV_`/`CS_`/`CT_`/`CO_`/`CR_`) | `CHANGING` | `CV_RESULT`, `CS_HEADER`, `CT_ITEM` |

- `TABLES`는 **사용하지 않습니다.** 값을 바꾸는지 읽기만 하는지 구분되지 않기 때문입니다. 테이블은 `USING`(읽기, `PT_`) 또는 `CHANGING`(변경)으로 넘깁니다.

## 오브젝트 배치 기준

| 패키지 | 무엇을 두나 | 예시 |
|---|---|---|
| 대표 모듈 (`$YCLAUDE_MD`) | 하위 영역 **두 곳 이상이 공통으로** 쓰는 오브젝트 | BP·MM 공통 클래스, 도메인, 구조 |
| 모듈 하위 (`$YCLAUDE_MD_001`) | **한 업무 영역**에서만 쓰는 오브젝트 | `_MD_001` BP, `_MD_002` MM |

- 처음엔 한 영역에서만 쓰다가 다른 영역에서도 쓰게 되면 대표 모듈 패키지로 옮깁니다.
- 참조는 하위 → 대표 모듈 방향만 허용합니다. (하위끼리, 대표 → 하위 참조 금지)
- 루트 `$YCLAUDE`에는 **데이터 엘리먼트·도메인만** 둡니다.
- 테이블·구조·테이블 타입은 항상 대표 모듈 패키지에 둡니다.

## 공통 오브젝트

| 오브젝트 | 위치 | 내용 |
|---|---|---|
| `YIF_CA_CONSTANTS` (인터페이스) | `$YCLAUDE_CA` | 공통 상수: 메시지 유형(`GC_MSGTY_*`), 기능 코드(`GC_UCOMM_*`), ALV 값 |
| `YCACOMMON` (Include) | `$YCLAUDE_CA_002` | 상위 Include. 아래 두 개를 순서대로 포함 |
| ├ `YCACOMMON_TOP` | 〃 | 공통 전역 데이터: `GV_OKCODE`, `GO_DOCKING`, `GO_GRID`, `GT_FIELDCAT`, `GS_LAYOUT`, `GS_VARIANT`, `GT_EXCLUDE` |
| └ `YCACOMMON_F01` | 〃 | 공통 FORM (`CA_` 접두어) |

**공통 FORM**

| FORM | 역할 |
|---|---|
| `CA_CREATE_CONTAINER` | Docking Container 생성 |
| `CA_CREATE_ALV` | ALV Grid 생성 |
| `CA_SET_FIELDCAT` | 내부 테이블 구조로 필드카탈로그 자동 생성 |
| `CA_SET_LAYOUT` | 기본 레이아웃(zebra, 열 너비 최적화, 다중 선택)·변형 |
| `CA_DISPLAY_ALV` | ALV 최초 출력 |
| `CA_REFRESH_ALV` | 스크롤 위치 유지하며 새로고침 |
| `CA_FREE_ALV` | ALV·컨테이너 해제 |
| `CA_EXIT_COMMAND` | `BACK`/`CANC` → 해제 후 `LEAVE TO SCREEN 0`, `EXIT` → 해제 후 `LEAVE PROGRAM` |

**사용 예**

```abap
REPORT ysd00100.

INCLUDE ycacommon.       " 공통 (데이터 + FORM)
INCLUDE ysd00100_top.    " 프로그램 전용 선언
INCLUDE ysd00100_scr.    " 선택 화면
INCLUDE ysd00100_o01.    " PBO
INCLUDE ysd00100_i01.    " PAI
INCLUDE ysd00100_f01.    " 프로그램 FORM

MODULE display_alv_0100 OUTPUT.
  IF go_docking IS INITIAL.
    PERFORM ca_create_container.
    PERFORM ca_create_alv.
    PERFORM ca_set_fieldcat USING gt_data CHANGING gt_fieldcat.
    PERFORM ca_set_layout CHANGING gs_layout gs_variant.
    PERFORM ca_display_alv CHANGING gt_data.
  ELSE.
    PERFORM ca_refresh_alv.
  ENDIF.
ENDMODULE.

MODULE exit_0100 INPUT.
  PERFORM ca_exit_command USING gv_okcode.
ENDMODULE.
```

- 화면의 OK 코드 필드 이름은 `GV_OKCODE`로 지정합니다.
- 공통 Include를 고치면 사용하는 **모든 프로그램**이 영향을 받습니다. 거의 바뀌지 않는 골격만 두고 업무 로직은 넣지 않습니다.

## 개발 규칙

| 항목 | 규칙 |
|---|---|
| ALV 컨테이너 | 기본은 **Docking Container** (`CL_GUI_DOCKING_CONTAINER`). 특정 화면 영역에 배치해야 하는 등 꼭 필요한 경우에만 Custom Container (`CL_GUI_CUSTOM_CONTAINER`)를 쓰고, 이유를 주석으로 남깁니다. |
| PBO의 ALV 처리 | ALV를 작은 MODULE로 쪼개지 않고 **ALV 전체(관련 메시지 포함)를 MODULE 하나**로 묶습니다. 그 안에서 `PERFORM`으로 단계별(컨테이너 생성, 필드카탈로그, 레이아웃, 이벤트, 출력/새로고침) 모듈화합니다. GUI STATUS/TITLE은 별도 MODULE. |
| PAI 종료 버튼 | `BACK`, `EXIT`, `CANC`는 GUI STATUS 기능 유형 `E`(Exit Command)로 지정하고 `MODULE exit_<화면번호> AT EXIT-COMMAND`에서 처리. (BACK·CANC → `LEAVE TO SCREEN 0`, EXIT → `LEAVE PROGRAM`) 나머지 기능 코드는 `user_command_<화면번호>`에서 처리. OK 코드는 `GV_OKCODE`. |
| 화면 MODULE 이름 | `<목적>_<화면번호 4자리>` (예: `status_0100`, `display_alv_0100`, `user_command_0100`) |

## SAP로 가져오기 (abapGit)

1. abapGit 실행 → **New Online**
2. URL: `https://github.com/reveurfutur/Claude_Code_SAP.git`
3. Package: `$YCLAUDE` (없으면 생성), Folder logic: **PREFIX**
4. **Pull** → 가져올 오브젝트 확인 후 실행

## 설정 (.abapgit.xml)

- Starting folder: `/src/`
- Folder logic: `PREFIX`
- Main language: `E` (영어)
